# 오류 해결

실습 중 실제로 마주친 초기 설정 문제를 먼저, 이후에는 실행 순서에 따라 정리했습니다. 오류에 표시된 문구로 해당 항목을 찾으세요. 명령은 VS Code의 터미널에서 저장소 폴더를 연 상태로 실행합니다.

## 1. `COPY_FROM_CHEATSHEET` 안내가 나옵니다

예시 코드가 아직 주석 안에 있거나 파일을 저장하지 않은 상태입니다. 이 오류가 나오면 거래는 전송되지 않았습니다.

1. 오류에 표시된 파일을 VS Code에서 엽니다.
2. `/* COPY_FROM_CHEATSHEET`부터 `END_COPY */`까지를 치트시트의 예시 코드로 교체합니다. 시작·끝 표시도 지웁니다.
3. 저장한 뒤 같은 명령을 다시 실행합니다.

첫 단계인 `01-deploy.mjs`를 실행할 때는 **`Payment.sol`도 함께 준비**해야 합니다.

## 2. `invalid private key`가 나옵니다

`.env`에 예시 값이 남아 있거나 개인키를 잘못 입력한 경우입니다. 다음 명령으로 실습 사이트의 테스트 개인키를 설정합니다.

```bash
npm run setup:account
```

입력한 키는 화면에 표시되지 않습니다. 설정이 끝나면 지급자 주소를 확인하고 다시 실행하세요. 이미 정상적인 `.env`가 있으면 기존 설정을 사용합니다.

다른 계정이 표시되면 터미널에 남아 있는 환경 변수가 우선 적용됐을 수 있습니다. 치트시트의 `env -u MAROO_PRIVATE_KEY -u MAROO_RECIPIENT`로 시작하는 실행 명령을 그대로 사용하세요. 실습 도중에는 계정을 바꾸지 않습니다.

## 3. 잔액이 부족하다고 나옵니다

지급액과 거래 수수료를 낼 테스트 토큰이 필요합니다.

[테스트 토큰 받기](https://faucet.maroo.io/)에서 **현재 지급자 주소**를 충전한 뒤 다시 진행하세요. 공유 계정은 다른 사람이 사용해 잔액이 줄어들 수 있습니다. 별도 계정으로 바꾸려면 진행자와 확인한 뒤 새 실습으로 시작합니다.

## 4. ‘실행 순서가 다릅니다’가 나옵니다

이미 끝난 파일을 다시 실행했거나 중간 단계를 건너뛴 경우입니다.

오류에 표시된 **‘다음 파일 번호’**에 해당하는 파일을 실행하세요. 예를 들어 다음 번호가 3이면 `03-pay.mjs`입니다. 처음부터 다시 하려면 [초기화·종료 안내](PARTICIPANT_GUIDE.md#초기화종료)를 따릅니다.

## 5. ‘이전 실행이 완료되지 않았습니다’가 나옵니다

거래를 보낸 뒤 응답을 기다리다 연결이 끊겼을 수 있습니다. **같은 지급을 바로 다시 보내지 마세요.**

1. VS Code에서 `.private/terminal/transactions.jsonl`을 열어 마지막 거래 해시를 찾습니다.
2. [테스트넷 익스플로러](https://explorer-testnet.maroo.io/)에서 해당 거래의 성공·실패·대기 상태를 확인합니다.
3. 진행자에게 거래 해시와 오류를 보여 주고, 완료된 단계부터 확인해 재개합니다.

`.private/file-lab/in-progress.json`은 중복 실행을 막는 파일입니다. 거래 상태를 확인하기 전에 삭제하지 않습니다. `compile` 오류로 멈춘 경우에도 이 파일이 남을 수 있으므로, `Payment.sol`을 수정한 뒤 진행자와 실행 기록을 확인하세요.

## 6. `InDenylist` 또는 `status: 0`이 나옵니다

**`04-deny.mjs`에서 나온 결과라면 정상적인 차단 동작입니다.** 보내는 계정을 차단 목록에 넣었기 때문에 지급이 거절된 것입니다.

수취인 잔액과 지급 횟수가 늘지 않았는지 확인하세요. 이어서 `restore-allow` 거래가 `status: 1`로 완료되면 차단 목록 복원까지 끝난 것입니다. 다른 단계에서 거절되거나 복원이 실패하면 다음 단계로 넘어가지 말고 진행자에게 알려 주세요.

익스플로러의 오류 설명이 깨진 문자로 보이면 터미널에 출력된 `InDenylist`와 함께 확인하세요. 화면의 깨진 문자만으로 다른 오류라고 판단하지 않습니다.

## 7. Docker가 실행되지 않습니다

먼저 Docker를 켠 뒤 연결 상태를 확인합니다.

```bash
docker info
```

- **macOS:** Docker Desktop이 실행을 마칠 때까지 기다립니다.
- **Linux:** Docker 서비스와 현재 계정의 실행 권한을 확인합니다.
- **WSL:** Docker Desktop의 WSL 연동을 확인합니다. `docker-credential-desktop.exe not found`가 나오면 진행자와 Docker 연동·경로 설정을 확인합니다.

메모리 부족으로 컨테이너가 종료되면 다른 작업을 닫고 Docker에 할당한 메모리를 확인하세요. 실습은 8GB 이상을 권장합니다. `/opt/lab/check-cpu`에서 지원하지 않는 환경으로 판정되면 진행자가 준비한 환경으로 전환합니다.

## 8. Privacy에서 `transaction not found` 또는 JSON 오류가 나옵니다

**`transaction not found`:** 거래가 아직 처리되거나 조회에 반영되지 않았을 수 있습니다. 잠시 기다린 뒤 치트시트의 마지막 `query tx` 명령만 다시 실행하세요. 예치나 지급 명령을 반복하지 않습니다.

**JSON 오류:** 결과 앞에 진단 메시지가 섞였을 수 있습니다. 치트시트에 있는 `sed`로 시작하는 거래 해시 추출 명령을 그대로 사용하세요. 저장된 출력에 `txhash`가 있다면 해당 거래부터 조회합니다.

## 현장에서 해결되지 않을 때

진행자는 아래 기록을 열어 결과 확인을 이어갑니다. **현재 실행이 아니라 미리 실행한 기록**임을 설명합니다.

- [PCL 실행 기록](../evidence/live-testnet/FINAL_USER_PCL_RUN.json): 정상 지급과 차단 결과
- [Privacy 실행 기록](../evidence/local/MANUAL_CLI_RESULT.json): 예치·지급 성공과 잔액 3/7

중단한 실습의 거래 상태와 정책 복원 여부는 별도로 확인합니다.
