# 70분 워크숍 진행안

대상: EVM·Solidity·JSON-RPC 경험이 있는 은행/핀테크 엔지니어. 목표는 PCL 정책 거절과 내 컴퓨터에서의 비공개 지급을 실행하고 두 환경의 증거·공개 범위를 구분하는 것입니다.

## 사전 준비

Node·Git·테스트 토큰·Docker를 준비하고 Privacy 소스 빌드와 개발용 증명 생성 파일 생성은 수업 전에 끝냅니다. 공개 테스트 계정은 동시 사용과 잔액을 보장하지 않으므로 참가자별 별도 계정이 권장됩니다. 운영자 키와 원본 privacy 로그는 화면에 띄우지 않습니다.

| 시간 | 설명·실습 | 성공 기준 |
|---|---|---|
| 0–8분 | 카페 A→원두업체 B 상황, 은행 승인과 체인에 기록된 정책의 경계 | 기존 은행 업무와 실습 역할 구분 |
| 8–15분 | EVM·프리컴파일, PCL·EAS·Privacy, 프록시 구조 | 요청→정책→구현체 순서 이해 |
| 15–34분 | 파일 01–04 실행 | 정상 status 1 / 차단 status 0 |
| 34–40분 | 거래 처리 결과·상태·가스비 해석 | 차단 후 잔액/횟수 불변 |
| 40–47분 | 비공개 잔액·증명 생성·공개 정보·감사 권한 | 로컬과 Maroo 차이 설명 |
| 47–62분 | deposit→transfer→list-notes | Alice 3 / Bob 7 / 반복 조회 일치 |
| 62–68분 | 실패 진단과 대화 | 정책 거부·자료 부재·인프라 장애 구분 |
| 68–70분 | 참고 링크, 각 조직의 적용 조건 | 후속 검증 항목 선택 |

70분은 계획값이며 전체 참가자 리허설 시간은 측정하지 않았습니다.

## 슬라이드별 발표 메모

1. 카페의 원두 대금으로 지급 통제와 거래 정보 보호를 두 실습에서 다룹니다.
2. 기업 심사와 서비스 이용 승인은 은행 업무입니다. 이번 코드는 심사나 사기 탐지가 아니라 관리자가 정한 송신자 차단 조건을 검사합니다.
3. 앱이 ethers로 지급을 요청하면 등록 프록시를 거쳐 체인에 내장된 정책 검사 기능을 사용합니다.
4. EAS는 자격 기록, PCL은 실행 조건, Privacy는 정보 공개 범위를 다룹니다. EAS는 개념과 별도 조사 결과만 소개합니다.
5. 사용자는 구현체가 아니라 프록시로 지급을 요청합니다. 실행 전후의 검사와 실패 시 변경 사항을 되돌리는 과정을 설명합니다.
6. 그림의 주소는 기존 배포 예시입니다. 참가자 새 배포 주소는 state.json에 저장됩니다.
7. 빈 차단 목록→정상 지급→카페 A 차단을 파일로 실행합니다.
8. 실패 해시만 보지 않고 수취 잔액과 지급 횟수를 비교합니다. 실패 거래의 가스비는 되돌아오지 않습니다.
9. 이후는 내 컴퓨터의 별도 Clairveil 환경입니다. 증명 생성 프로그램은 비공개 데이터를 다루므로, 실행 위치와 키를 누가 관리하는지 살펴봅니다.
10. Privacy 상세 흐름을 설명합니다. 공개 예치 후 지갑이 지급 입력을 준비하고, 증명 생성 파일을 사용해 증명을 만듭니다. 로컬 체인이 이를 검증해 지급을 반영하면 각자 키로 잔액 3/7을 조회합니다. 이 흐름은 PCL과 연결한 실행이 아닙니다.
11. 예치 10, 지급 7, Alice 3/Bob 7을 확인합니다. 이는 Maroo Privacy 호환 증거가 아닙니다.
12. 이번 실험에서 실제로 관찰한 결과와 자료 부족으로 실행하지 못한 부분을 분리합니다.
13. 실습·공식 문서·시뮬레이션 체험 링크를 소개합니다.

대화 주제로 “거래 해시가 있어도 지급 성공이 아닌 경우는 무엇인가?”, “내 컴퓨터에서의 성공만으로 Maroo에서도 성공했다고 할 수 없는 이유는 무엇인가?”를 사용합니다. 본문 코드는 완성 예시이며 참가자에게 빈칸 과제를 요구하지 않습니다.

서비스 장애 시에는 거래 처리 결과 JSON과 로컬 결과를 열어 **기존 실행 기록**이라고 밝히고 상태 변화를 설명합니다. 실시간 실행을 한 것처럼 연출하지 않습니다. 상세 대응은 [오류 해결](TROUBLESHOOTING.md)에 있습니다.

워크숍 이후 각 조직은 4~8주 PoC에서 관리자·발급자 권한, 키 보관·관리, 공개 정보, 감사자 접근권한, 테스트넷에 맞는 증명 자료와 입력 데이터 준비 방법, 장애 재처리 기준을 검증합니다. 별도 마무리 강의를 늘리기보다 후속 검토 메모로 제공합니다.
